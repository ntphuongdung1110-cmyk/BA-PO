# Bảng theo dõi tiến độ & Rubric tự chấm

## Cách chấm (0–4)

| Điểm | Ý nghĩa |
|---|---|
| 0 | Chưa làm được |
| 1 | Làm được khi có template / hướng dẫn |
| 2 | Tự làm được với case quen thuộc |
| 3 | Tự làm được với case mới và giải thích được trade-off |
| 4 | Review / coaching được người khác, cải tiến cách làm của team |

## Rubric năng lực cuối khoá

| Năng lực | Junior | Middle | Senior target | Điểm đầu khoá | Điểm Day 28 | Điểm Day 56 |
|---|---|---|---|---|---|---|
| Problem Analysis | Ghi lại request | Tìm problem và impact | Dùng evidence, root cause, metric, trade-off | | | |
| Stakeholder | Trao đổi theo yêu cầu | Chủ động workshop, follow-up | Điều phối conflict, decision, expectation | | | |
| Process Analysis | Vẽ flow happy path | AS-IS/TO-BE có exception | Tối ưu quy trình, thấy rủi ro chuyển đổi | | | |
| Requirement | Mô tả chức năng | Có flow, rule, AC | Atomic, testable, traceable, đủ exception/NFR | | | |
| System Analysis | Hiểu UI, field | Hiểu API, data, flow | Integration, race, retry, idempotency, audit | | | |
| UX/UI | Mô tả màn hình | Đủ field, validation | Đủ state, permission, edge case, trợ năng | | | |
| Product Thinking | Nhận feature | Biết priority, MVP | Quyết định theo value, data, risk, opportunity cost | | | |
| Delivery | Hỗ trợ clarification | Theo refinement, UAT | Quản lý change, release, monitoring, outcome | | | |

**Mục tiêu sau 56 ngày:** tối thiểu 2 điểm mọi nhóm; 3 điểm ở Requirement, System Analysis và một nhóm theo định hướng (BA → Process; PO → Product Thinking).
